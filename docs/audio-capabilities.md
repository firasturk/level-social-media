# Audio for a post's video: what each source can and cannot do

Read-only research for the Audio option of the Video flow (docs/video.md "Audio"), written on
22 October 2026 from the providers' own documentation. No key was used and nothing was called;
every claim below is marked **Verified** (the page is named and the sentence quoted) or
**Assumed** (our reading, not stated by the provider). Prices are stated where a page gives them,
and "not published" where none does.

## 1. Instagram / Meta Graph API: Reels and the music library

**Can a Reel published through the API carry a track from Instagram's music library? No.** The
Reels container takes a `video_url` (the finished file, sound included) and the only audio field
is `audio_name`, which *names* the audio that is already in the file. There is no field that
picks a library track; that is done in the Instagram app when posting by hand. In the studio this
is therefore a note on the version ("Added on Instagram at publishing"), not a feature.

| --- | --- | --- |

What this means for the clip we make: Higgsfield's mp4 (H.264 + AAC where the engine makes sound)
fits the Reel specification as long as `moov` is at the front; the studio already records
`faststart`, `codecs`, `width`, `height` per clip (docs/video.md). Our clips are 5–15 s, above the
3 s minimum.

## 4. The browser and the Worker

| Claim | Source | Status |
| --- | --- | --- |
| Web Audio can decode and mix tracks off-line: "an OfflineAudioContext doesn't really render the audio but rather generates it, as fast as it can, in a buffer"; `decodeAudioData` makes an `AudioBuffer` from a file; Baseline "Widely available … since April 2021" | https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API | **Verified** |
| WebCodecs encodes: "enables web developers to encode and decode video and audio in the browser efficiently (using hardware acceleration)"; `VideoEncoder` "Encodes VideoFrame objects.", `AudioEncoder` "Encodes AudioData objects."; **it does not mux**: "It does not provide a built-in way to read EncodedVideoChunk objects from a video file, or write them to a playable video file." — a JS muxer (mp4 boxes) is needed to make the mp4 | https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API | **Verified** |
| Codec availability is per browser: "The WebCodecs specification supports a particular set of codecs, and individual devices and browsers may only support a subset of those."; `VideoEncoder.isConfigSupported()` "checks if VideoEncoder can be successfully configured with the given config" (HTTPS only) | MDN, https://developer.mozilla.org/en-US/docs/Web/API/VideoEncoder/isConfigSupported_static | **Verified** |
| H.264 and AAC are proprietary codecs "Limited to Google Chrome": the Chromium project lists "H.264 / AVC" under "Proprietary Video Codecs (Limited to Google Chrome)" and "AAC (Main, LC, HE profiles only)" under "Proprietary Audio Codecs (Limited to Google Chrome)"; the Chromium `ffmpeg_branding` "builds default set of codecs" while the Chrome value "includes additional proprietary codecs (MP3, etc..)" | https://www.chromium.org/audio-video/ | **Verified** (so an open-source Chromium build, and browsers built from it without the licence, cannot encode the H.264/AAC mp4 Instagram wants) |
| Support: WebCodecs in Chrome and Edge from 94, Firefox from 130, Safari full from 26.0 with 16.4–18.7 "Partial support" | https://caniuse.com/webcodecs | **Verified** (caniuse does not say which part is missing in Safari 16.4–18.7; test on the team's iPhones before relying on it) |
| The pragmatic path: decode the clip's frames (`VideoDecoder` or a `<video>` drawn to canvas), mix the clip's sound with the track in an `OfflineAudioContext`, encode AAC + H.264 with WebCodecs where `isConfigSupported` says yes, mux with a JS mp4 writer, upload the result as a new version (`POST /api/studio/posts/video/upload`) | our design for the Video editor branch | **Assumed** |
| Cloudflare Workers cannot render or mux video: an isolate is JavaScript/WebAssembly with "up to 128 MB of memory, including the JavaScript heap and WebAssembly allocations", CPU "from the default 30 seconds to 5 minutes (300,000 ms)" on the paid plan; there is no process, so no ffmpeg. A WebAssembly ffmpeg would have to fit the 128 MB and the CPU budget for a 60 MB clip | https://developers.cloudflare.com/workers/platform/limits/ | **Verified** (limits), **Assumed** (that a wasm ffmpeg does not fit; not tried) |
| Cloudflare's own media products (Stream, Media Transformations) transcode but do not take a second audio track to mix; Cloudflare Containers would run ffmpeg but are a separate paid product | general knowledge, not read on 22 Oct | **Assumed** |

## 5. What the Audio option can offer today

| Option | How | State |
| --- | --- | --- |
| Engine sound (the provider's generated audio, on/off) | `settings.audio` → `generate_audio` / `sound` per model, only where the catalog's `audio` is set | **Available now** (Higgsfield key, admins; cost in the clip's estimate) |
| No sound | `settings.audio: false` | **Available now** |
| Upload a licensed track | `POST /api/studio/posts/video/audio/upload` stores it (mp3/m4a/aac/wav, 25 MB) with a licence line; the choice is written on the version. **Muxing happens in the browser-side Video editor, not on the server**; the clip's file is unchanged until then | **Available now** (storage and choice, admins; free). The mix waits for the editor branch |
| Generated music | Magnific: Lyria 3 / Lyria (API) or `audio_music_generate` and `video_music` (MCP); Higgsfield: no music endpoint, only audio *references* on reference-to-video workflows | **Needs a key** (Magnific key or MCP OAuth under Connection). Confirm-before-spend, estimate from `simulate_cost` / none published → blocked until clarified. `POST /audio/generate` answers 503 "not connected" today |
| Sound effects / voiceover | Magnific `POST /v1/ai/sound-effects`, `POST /v1/ai/voiceover` (ElevenLabs) | **Needs a key**; same rules; not wired |
| Mixing on a server | Magnific MCP `video_audio_mix` ("Lay an existing audio track over a clip and mix the two. Free.") | **Needs a key** (MCP OAuth); not wired; a copy of the clip leaves our storage |
| Instagram music library | Only inside the Instagram app at posting | **Not possible via API** — the studio keeps the note "Add music on Instagram when publishing" on the version |
| Instagram Reel with the audio baked in | `media_type=REELS` + `video_url` (H.264/AAC, moov first, 3 s–15 min, ≤ 300 MB, 9:16 recommended) | **Possible via API**, not built (docs/publish.md: pictures and carousels only) |
