# Source system: Max Fashion Studio

What exists today, where it lives and what Level Social Media does with it. Paths are relative
to the repository root of `firasturk/max-fashion-studio` (branch `main`, October 2026).

## Runtime

- One Cloudflare Worker (Workers Paid, `cpu_ms: 300000`) serves the Hono API under `/api/*` and
  the Vite-built React SPA from `dist/client`. `wrangler.jsonc` holds vars; `wrangler.deploy.json`
  is generated by `scripts/embed-assets.mjs` on deploy.
- D1 (`DB` binding, SQLite) for state, R2 (`BUCKET`) for every image. Migrations in `migrations/`
  (0001–0015), applied with `npx wrangler d1 migrations apply <db-name> --remote`.
- Cron `* * * * *` runs `advanceBatch` for every running batch and `readPendingReferences`
  (vision reads of library photos, four per minute).
- Build and deploy: `pnpm check` (typecheck under `tsconfig.worker.json` for server/shared/tests,
  eslint, vitest, vite build) then `pnpm run deploy`. Deploy needs `CLOUDFLARE_API_TOKEN` and
  `CLOUDFLARE_ACCOUNT_ID` in the environment.
- `wrangler.jsonc` `alias` must list every `@shared/*` module; a missing alias fails the Worker
  build only, not `pnpm check`.

## Engines and keys

| Engine                                      | File                   | Auth                                                              | Notes                                                                                                                    |
| ------------------------------------------- | ---------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Google Nano Banana Pro / 2 / 2.1 (API key)  | `server/google.ts`     | setting `google_api_key`                                          | Flex background jobs via `makeGoogleApiClient`                                                                           |
| Google Vertex AI (same models, GCP billing) | `server/vertex.ts`     | setting `vertex_service_account` (service-account JSON, location) | Preferred when present (`resolveGoogleAuth`); GA image id `gemini-3-pro-image`, location `global`; text via `vertexText` |
| OpenAI GPT Image + GPT-4.1 mini vision      | `server/openai.ts`     | setting `openai_api_key`                                          | Stand-in for vision when Google fails; `isBadKey` guard                                                                  |
| fal.ai Seedream                             | `server/fal.ts`        | setting `fal_api_key`                                             |                                                                                                                          |
| Higgsfield Cloud                            | `server/higgsfield.ts` | secret `HIGGSFIELD_API_KEY` or setting                            | Original engine, webhook optional                                                                                        |

All keys are stored through `setSetting` (encrypted) and never returned. The Connection dialog
(`src/studio/ConnectionDialog.tsx`) has one tab per vendor and remembers the last tab.

Engine selection per batch is `config.model` (slug); `makeGoogleClient(env)` returns the API-key
or Vertex client. Concurrency: `concurrency(env)` from `MAX_CONCURRENT_GENERATIONS`, Vertex drops
to 2 for ten minutes after a 429 (`vertexThrottledUntil`).

## Data model today

| Table               | Purpose                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `users`, `sessions` | auth                                                                                                                |
| `batches`           | one Generate session: `config` JSON, `state` idle/running/paused                                                    |
| `sources`           | uploaded photos: `stem`, `key`, `reference_key`, `role`, `framing`, `skill`, `look`                                 |
| `tasks`             | one output: `card`, `status`, `prompt`, `brief`, `output`, `qa`, `cost`, `model`, `attempts`, `request_id`, `lease` |
| `identities`        | saved generated faces                                                                                               |
| `refs`              | library photos: `skill` (scope key), `key`, `name`, `framing`, `notes` (vision read)                                |
| `skills`            | team skills: `title`, `caption`, `description`, `goal`, `library`, `hidden`                                         |
| `looks`             | saved prompts per skill                                                                                             |
| `settings`          | key/value, values encrypted; includes `direction_rules`, `zaid_skill`, `modes_config`, vendor keys                  |
